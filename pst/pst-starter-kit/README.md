# PST Starter Kit

Everything you need to build your own **Problem-Solving Teaching (PST)** units — teacher-facing
**Problem-Based Learning** activities where students work a real, ill-structured problem as a
**stakeholder** while the teacher guides. Self-contained (runs in a browser), a built-in
**7-language switcher** (English, Spanish, Vietnamese, Arabic, Hindi, Urdu, Chinese; Arabic & Urdu
right-to-left), no accounts, no server, no data collection.

This kit is a **self-contained copy** of the runtime + translation engine, the arcade engine, the PD
(teacher-support) tooling, the full blueprint, and one **complete working example unit** you can open
and pull apart. Nothing here calls back to the parent project.

> 📦 **Download the whole kit as a ZIP:** [`pst-starter-kit.zip`](../pst-starter-kit.zip)
> (ready to unzip; no build step needed to just open the example).

> **Read [`pst_project_pack.md`](pst_project_pack.md) first.** The engine and translations are
> commodity — the *quality* of a PST unit lives in the problem design and the surface → deep →
> transfer sequence (§2–§4).

## Quickstart

**1. Try the example.** Serve the folder and open `example/index.html`. Walk the three phases, notice
the surface→deep gate, and use the 🌐 menu to switch English ⇄ any of the 7 languages (Arabic & Urdu
flip right-to-left). Every language except English falls back to English per key — that fallback is
what lets you **ship English first and translate later**.

**2. Make your own unit.** Copy `example/` and edit the **English** content. Keep the shape:
- six pages — `index / surface / deep / transfer / facilitator-guide / assessment` — plus `i18n-unit.js`;
- build **surface → deep → transfer**, with the **PBL problem gated** behind surface + deep;
- **tag every activity** with a real TEKS SE and a named high-effect strategy + its *d* (project pack §3–§4);
- the transfer phase runs the PBL arc: Meet the Problem → stakeholder roles → Know/Need-to-Know →
  investigate → solution product → debrief (§3.4).

**3. Translate.** Key the body with `data-i18n`/`data-i18n-html` (page prefixes `ix./sf./dp./tr./fg./as.`),
register an English dictionary, then add the other six languages with an **identical key set/order**
per language and **HTML tags + URLs left byte-identical** (project pack §6). Skip a language and the
runtime falls back to English for it. Parallel AI agents work well — one unit each. Then:
```bash
node validate.js example          # parity across all 7 languages + every HTML key present
```

**4. Add arcade tickets** (optional, retrieval practice — project pack §12). Author
`games/data/<unit>.js` (six tickets: entry+exit × the three phases). **Copy the answer index `a`,
category index `c`, and choice order byte-identical across every language** — translating must not
reorder choices. Then:
```bash
node validate.js --tickets example/example-tickets.js   # confirms indices are preserved
node build-tickets.js                                    # → games/tickets.js (do not hand-edit)
```
Wire an entry `.tkpill` at the top and an exit `.tkpill` at the bottom of each phase page, linking
`…/games/index.html?t=<id>`, and add `tk.entry`/`tk.exit` label keys to the unit dictionary.

**5. Teacher-support pages** (UDL / ELPS / lesson-plan guide). The cores are **generic — reuse them
unchanged**; only `_pd/suite/en.json` is suite-specific.
```bash
# a) edit _pd/suite/en.json — your suite key (e.g. "pst") + wording; add es/vi/ar/hi/ur/zh to ship 7 langs
# b) edit gen-pd-pages.js — set the SUITES map (folder key + theme colors)
node build-pd.js       # → assets/*-core-i18n.js + assets/pd-suite-i18n.js
node gen-pd-pages.js   # → <suite>/udl.html, elps.html, guide.html
```

**6. Privacy + verify before you ship** (project pack §16):
- Copy `policy.template.html` → `policy.html`, fill it in, link it from every footer.
- `node validate.js <unit>` — 7-language parity + every HTML key covered.
- **Render every unit in a real headless browser** (English + one non-English + one RTL) — correct
  `dir`, translated `h1`, no console errors. A key that never renders only shows up here.
- Commit the **whole unit folder** (keyed HTML *and* `i18n-unit.js` together) — shipping one without
  the other ships a broken unit.

## Translation notes

- One unit (or one ticket file) per AI agent works well; run a few at a time.
- **Keep every language's key set identical** to English; for `data-i18n-html` values and ticket
  content, translate only the human-readable text — leave HTML tags, attributes, URLs, TEKS codes,
  effect-size labels, and (for tickets) the answer/category indices exactly as English.
- Arabic & Urdu are RTL — translate normally; the engine sets `dir` for you.
